# 游戏运营后台与服务端测试计划

## 1. 测试目标

验证管理页面、HTTP API、鉴权权限和核心游戏业务在隔离环境中的正确性，并提供可重复执行、可定位失败、可生成报告的自动化回归基线。

## 2. 测试对象

- Web 管理页面：`/admin`、`/admin/ui`
- 系统能力：健康检查、运行配置、Prometheus 指标
- 账号体系：注册、登录、改密、刷新 Token、会话、玩家资料
- 后台能力：管理员登录、权限隔离、玩家/背包查询、审计与分页查询
- 业务闭环：好友、聊天、邮件、奖励、任务、商城、抽卡、掉落

## 4. 准入与退出条件

准入条件：服务可执行文件存在，`/health` 在20秒内就绪；快速套件运行在 `in_memory`，集成套件运行在独立 MySQL 库和 Redis DB。

退出条件：默认套件全部通过；失败报告包含请求方法、路径、预期状态、实际状态与响应体摘要；HTML和JUnit报告可生成。

## 5. 风险控制

- 每次运行使用唯一账号名，减少用例之间的数据耦合。
- 默认自动选择空闲端口，避免与开发服务冲突。
- 测试服务使用独立进程并在会话结束后回收。
- 默认不连接真实数据库，不修改开发或生产数据。
- 外部依赖场景与快速回归分开执行，失败原因更容易定位。
- 云端脚本要求本地 MySQL/Redis、空的非生产 Redis DB，自动创建并清理临时 MySQL 用户和库；锁定 Redis DB 防止并发清理。
- 测试用户共用回环IP，测试进程将每IP注册上限调整为1000，避免超过默认30次造成用例互相干扰；不修改生产配置。本套件不代表注册限流专项验证。
- 发奖故障仅在 `game_backend_it_*` 临时库通过定向CHECK约束注入，不修改MySQL全局参数；结束后移除约束，验证恢复重试。
