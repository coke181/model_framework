# model_framework 后端项目面试题与参考答案

> 面向 C++ 游戏后端、客户端后端协作和服务端开发岗位。本文按零基础组织，项目问题给参考答案，通用基础问题也给简要答案。项目是可复用的游戏业务后端骨架，不应描述成已经具备完整商业级支付、跨区和大规模集群能力。

## 一、项目介绍

### 1. 请用一分钟介绍项目

**参考答案：**

这是一个基于 C++20、Boost.Asio、Boost.Beast、Boost.JSON、MySQL、Redis 和 OpenTelemetry 开发的可复用游戏业务后端骨架，服务于 Unreal Engine 等游戏客户端。当前包含账号认证、玩家资料、好友、聊天、邮件、奖励、任务、商城、抽卡、掉落、多人房间和 LiveKit 语音鉴权等功能。

工程拆分为 HTTP API 服务、WebSocket 聊天网关和后台任务 Worker。业务层按认证、玩家、聊天、邮件、任务、商城、抽卡、多人和语音领域拆分；存储层使用 Repository 接口隔离 MySQL、Redis 和内存实现；横切层提供环境变量配置、日志、错误码、鉴权、请求 Trace、Metrics 和数据库迁移。

### 2. 三个可执行程序分别做什么？

`hello_service` 提供登录、玩家、邮件、好友、任务、商城、抽卡和后台 HTTP 接口；`hello_chat_gateway` 维护 WebSocket 长连接、聊天鉴权、频道加入和实时广播；`hello_task_worker` 轮询后台任务表，执行定时公告、批量邮件和批量奖励。

这样拆分后，聊天长连接不会阻塞普通 HTTP 请求，耗时或可重试的运营任务也不会占用用户请求生命周期。

### 3. 为什么不把所有代码写在路由文件里？

Router 只负责路径匹配，Handler 负责解析请求和组织响应，Service 负责业务规则，Repository 负责数据访问。这样同一个 Service 可以被 HTTP、Worker 和测试复用，也能把 MySQL 实现切换成 Redis 或内存实现。

## 二、C++ 和网络基础

### 4. Boost.Asio 的事件循环是什么？

事件循环等待 Socket、定时器和异步任务完成，事件发生后执行回调。多个线程可以共同运行 `io_context`，但共享连接状态必须使用 Strand、锁或单线程执行约束。

### 5. 异步回调有哪些生命周期风险？

回调可能在拥有者销毁后执行，捕获局部引用可能变成悬空引用，多个回调还可能并发修改同一状态。项目中应使用安全弱引用、值捕获、取消 Socket/Timer，并在服务关闭时停止接受新任务。

### 6. `unique_ptr`、`shared_ptr` 和 `weak_ptr` 如何选择？

`unique_ptr` 表示唯一所有权；`shared_ptr` 表示共享生命周期，适合异步操作共同持有的服务或配置；`weak_ptr` 只观察不延长生命周期，适合防止异步回调保活已无效对象或产生循环引用。

### 7. HTTP 与 WebSocket 的区别是什么？

HTTP 是一次请求对应一次响应，适合登录、查资料、购买和领奖；WebSocket 在 HTTP Upgrade 后保持长连接，双方都能主动发送，适合聊天、在线状态和实时信令。WebSocket 额外需要心跳、重连、鉴权失效和广播管理。

### 8. 什么是 TCP 粘包？

TCP 只保证字节流，不保留应用层消息边界。一次读取可能得到半条或多条消息，因此协议必须带长度字段、分隔符或使用完整帧解析。WebSocket 框架已经处理帧边界，但业务 JSON 仍要校验完整性和大小限制。

## 三、HTTP 架构

### 9. 一个请求如何经过项目？

Beast 接收并解析请求，Router 按 method/path 匹配 Handler；中间件处理 Trace、日志、鉴权和异常；Handler 解析 JSON；Service 校验业务规则；Repository 访问 MySQL/Redis；最后统一序列化 JSON，并返回 Trace ID 和响应耗时。

### 10. 为什么需要统一错误码？

客户端应依据机器可判断的 code，而不是依赖可变的中文 message。400 通常是字段错误，401 是未认证，403 是无权限，404 是资源不存在，409 是状态冲突，429 是限流，500 是服务异常。错误响应不应泄露 SQL 或堆栈。

### 11. 为什么需要 Trace ID？

一个请求可能调用 Service、MySQL、Redis 或 LiveKit。Trace ID 能把同一请求的 HTTP、任务和数据库 span 串起来，快速判断耗时来源。项目通过响应头返回 `X-Trace-Id`，并提供最近 span 调试和 OTLP 导出。

## 四、账号和安全

### 12. 注册和登录怎么实现？

注册时校验账号和密码，检查重复账号，使用 Argon2id 生成密码哈希并保存账号和玩家资料。登录时读取账号、校验 Argon2id、检查冻结/封禁状态，创建 Session，签发 Access Token 和 Refresh Token。

### 13. 为什么不能存明文密码？

数据库泄露后明文密码可以直接被使用。密码必须使用带盐的慢哈希算法，例如 Argon2id；普通 SHA-256 太快，不适合直接作为密码存储方案。

### 14. Access Token、Refresh Token 和 Session 的关系是什么？

Access Token 生命周期短，用于访问玩家 API；Refresh Token 生命周期长，用于换取新的 Access Token；Session 记录账号、设备、过期时间和撤销状态，使服务端能够踢下线、单端登录和撤销刷新能力。

### 15. 为什么生产环境禁用 quick-login？

quick-login 只适合开发测试。如果生产环境允许客户端只传任意名称换 Token，玩家可以冒充其他账号。项目通过 development/staging/production 环境控制，production 强制关闭 quick-login 和开发管理员自动创建。

### 16. 如何处理 401？

客户端先尝试用 Refresh Token 刷新会话，并保证刷新请求串行，避免多个请求同时刷新。如果刷新失败，清理会话并重新登录。不能无限重试 401，否则会产生请求风暴。

### 17. 如何保护管理员接口？

管理员使用独立登录和 Bearer 会话，后端根据管理员账号和权限表检查权限。玩家 Token 不能调用批量发奖、封禁、公告和商城配置接口。高风险操作要记录操作人、目标、参数摘要、结果和 Trace ID。

## 五、MySQL、Redis 与一致性

### 18. MySQL 和 Redis 如何分工？

MySQL 保存账号、玩家资料、背包事实、好友关系、聊天历史、邮件、奖励流水、审计和权限。Redis 保存 Session、刷新 Token 索引、验证码、限流、黑名单、聊天最近窗口、未读数、离线消息和在线状态等热点或短期状态。

### 19. Repository 模式有什么价值？

Service 只依赖 `AccountRepository`、`MailRepository` 等接口，不依赖具体 SQL。MySQL、Redis 和内存实现可以替换，便于本地 review、单元测试和未来迁移数据库。

### 20. 什么是事务？哪些功能必须用事务？

事务保证多个数据库操作要么全部成功，要么全部回滚。邮件领奖、商城购买、抽卡、任务领奖和掉落拾取都需要在同一事务中完成扣除资源、写奖励流水、增加资产和更新状态。

### 21. 什么是幂等？如何防止重复领奖？

同一请求重复执行不能重复产生副作用。可以使用客户端 request_id、服务端固定 grant_id、唯一索引和事务状态判断。任务奖励可使用 `quest:{player_id}:{quest_id}` 作为稳定流水 ID，重复请求返回已处理结果。

### 22. Redis 缓存失效后怎么办？

先定义 MySQL 是否是权威来源。玩家资产和奖励通常以 MySQL 为事实，Redis 只是缓存；缓存丢失时从 MySQL 回源重建。热点 Key 还要考虑缓存穿透、击穿、雪崩、TTL 抖动和互斥刷新。

### 23. 数据库迁移为什么要加锁？

HTTP 服务、聊天网关和 Worker 可能同时启动，若同时执行 ALTER TABLE 会产生冲突。项目通过 MySQL `GET_LOCK` 串行化 migration，SQL 使用幂等写法；生产环境也可以关闭自动迁移，改用人工发布流程。

## 六、游戏业务

### 24. 邮件领取奖励的后端流程是什么？

验证玩家身份、邮件归属、未删除、未过期和未领取；开启事务，写奖励流水、增加 gold/gem/item、标记附件已领取；提交后返回最新邮件和玩家资料。重复领取根据幂等流水返回已处理状态。

### 25. 为什么抽卡结果和商城价格必须由后端决定？

客户端不可信，不能本地扣货币、决定概率或生成奖励。后端读取卡池/商品配置，校验玩家余额和限购，使用事务扣除资源、生成结果、发放奖励并写历史。UE 只展示结果并刷新后端返回的权威资产。

### 26. 好友申请如何避免重复关系？

服务端校验不能申请自己、目标存在、双方不是好友、没有相同 pending 申请；数据库用唯一约束和事务处理并发请求。申请状态应明确区分 pending、accepted、rejected 和 cancelled。

### 27. 聊天为什么区分大厅、房间和好友私聊？

三类频道的成员权限、生命周期、历史范围和未读语义不同。项目使用 lobby、room、friend_direct 三种频道模型，私聊频道由双方玩家 ID 生成稳定标识，防止私聊误广播。

### 28. WebSocket 聊天流程是什么？

连接后发送 auth 和 HTTP 登录拿到的 Token；网关验证并绑定玩家；客户端 join 频道；say 消息经过频道权限、禁言、黑名单、频率和长度校验后写入历史并广播。断线重连后必须重新鉴权、重新 join，并通过离线接口补拉消息。

### 29. LiveKit Token 为什么必须后端签发？

LiveKit API Secret 不能放在 UE 客户端。后端验证游戏 Token 和房间成员资格后签发短期 LiveKit JWT，并根据禁言、封禁和审核状态设置权限。

## 七、任务和后台 Worker

### 30. 为什么批量发奖需要后台任务？

批量操作可能处理大量玩家，不能让一个 HTTP 请求长时间等待。接口先写入任务表，Worker 按 scheduled -> running -> completed/failed 执行，保存成功/失败项，失败项可以重试，形成补偿闭环。

### 31. 多实例部署时定时任务有什么问题？

多个 Worker 可能重复执行同一任务。需要数据库锁、Redis 分布式锁、任务租约、唯一执行 Token 或把任务调度器独立出来。仅靠进程内 bool 只能适用于单实例。

### 32. 任务重试为什么可能造成重复发奖？

第一次请求可能已经成功写资产但响应丢失，Worker 认为失败再次执行就会重复奖励。因此奖励操作必须使用固定幂等 ID、唯一约束和事务，而不能只依赖任务状态。

## 八、监控、部署和排错

### 33. Metrics 和 Tracing 的区别是什么？

Metrics 是聚合统计，如请求数、错误数、任务耗时和 P95；Tracing 是单次调用链，如 HTTP -> Service -> MySQL -> Redis。项目通过 `/metrics`、`/debug/traces` 和 OTLP Collector 同时提供本地调试与外部观测。

### 34. 如何定位接口慢？

先看整体耗时和 Trace，再拆解路由、Service、SQL、Redis 和外部 API。数据库慢要看索引、执行计划、锁等待和连接池；线程排队慢要看 IO 线程是否执行阻塞操作；响应大则检查 JSON 和网络发送。

### 35. 为什么不能在 IO 线程执行慢 SQL？

IO 线程负责处理很多连接，如果执行阻塞 SQL 或文件 IO，其他玩家请求也会被拖住。应使用异步接口、独立线程池或任务队列，并在完成后安全地回到连接执行上下文。

### 36. Linux 部署需要什么？

HTTP 服务、聊天网关和 Worker 作为 systemd 服务运行，MySQL 和 Redis 提供存储，Nginx 可作为 TLS 和反向代理。生产环境要关闭 quick-login 和开发管理员自动创建，不把 MySQL 3306 与 Redis 6379 暴露到公网。

## 九、后端基础知识详解

### 37. 什么是值语义和引用语义？

值语义表示复制后两个对象相互独立；引用语义表示多个变量指向同一个对象。请求 DTO 通常适合值语义，连接、服务和缓存对象通常需要明确共享或唯一所有权。选择错误会导致不必要复制或生命周期失控。

### 38. 什么是移动语义？

移动语义把临时对象持有的资源转移给新对象，避免深拷贝。网络响应、JSON 文档和大型容器返回时可以利用移动语义减少复制，但移动后的对象只能保持有效但未指定的状态，不能继续假设原内容存在。

### 39. 原子变量、互斥锁和读写锁如何选择？

单个计数器或标志可以使用原子变量；多个字段需要保持一致时使用互斥锁；读多写少且临界区合适时可以使用读写锁。项目的请求统计可以使用原子计数，聊天成员和任务状态这类复合结构不能只靠一个原子变量保护。

### 40. 什么是生产者消费者模型？

生产者把任务放入队列，消费者从队列取出执行，中间用互斥锁、条件变量或无锁结构同步。后台任务 Worker 可以把 HTTP 创建的任务作为生产者，把任务表轮询或队列执行作为消费者。队列需要容量、超时、失败和关闭语义。

### 41. 什么是连接池？

连接池预先或按需维护一组数据库连接，请求使用完后归还，而不是每次重新建立 TCP、TLS 和数据库会话。连接池必须限制最大数量、设置获取超时、检测失效连接，并避免连接泄漏。

### 42. 什么是反压？

当生产速度大于消费速度时，系统必须限制生产、排队或丢弃低价值任务，这叫反压。WebSocket 广播、批量邮件、日志和后台任务都需要反压，否则内存队列可能无限增长。

### 43. 什么是线程安全？

多个线程同时调用或访问一个组件时，结果仍符合预期。线程安全不只是“没有崩溃”，还包括状态原子性、顺序、可见性和生命周期。共享聊天状态、Session 索引和 Metrics 都要明确并发策略。

### 44. 什么是内存可见性？

一个线程写入的数据不一定立即按预期被另一个线程读取。原子操作、锁、条件变量和正确的内存序可以建立 happens-before 关系。不要用普通 bool 代替线程同步。

### 45. 什么是 CPU 上下文切换？

线程切换需要保存和恢复寄存器、调度状态，并可能造成 Cache 失效。线程不是越多越好，Asio IO 线程、数据库线程和 Worker 数量要根据阻塞情况、CPU 核数和负载测试确定。

### 46. 什么是 HTTP 方法的幂等性？

GET 通常应该是安全且幂等的，PUT 可以设计成幂等更新，POST 通常可能产生新资源或副作用。即使使用 POST，也可以通过 request_id 让领奖、购买和发奖业务具备应用层幂等性。

### 47. 什么是 TLS？

TLS 通过证书验证服务端身份，并协商会话密钥对通信加密和完整性保护。正式环境应使用 HTTPS/WSS，不能把密码、Token 和后台请求通过明文 HTTP 暴露在公网。

### 48. 什么是 CORS、CSRF 和 XSS？

CORS 是浏览器跨源访问控制；CSRF 是利用浏览器自动携带凭据伪造请求；XSS 是把恶意脚本注入页面。纯 UE 原生客户端受浏览器限制较少，但后台 Qt/Web 页面仍需处理 CORS、CSRF、输出转义和 Content-Security-Policy。

### 49. 什么是 SQL 注入？

攻击者把 SQL 片段混入用户输入，改变查询语义。必须使用参数化查询或预编译语句，不能拼接登录名、玩家 ID、搜索条件和排序字段。动态排序字段也要使用白名单映射。

### 50. 什么是密码加盐和 Pepper？

Salt 是每个密码独立保存的随机值，防止相同密码产生相同哈希并抵抗彩虹表；Pepper 是不放在数据库中的额外服务端秘密。Argon2id 本身需要正确的参数、盐和升级策略。

### 51. 什么是数据库索引？

索引是帮助数据库快速定位记录的额外数据结构，通常使用 B+Tree 或 Hash。它会增加写入、空间和维护成本，因此应根据查询条件、排序、唯一约束和执行计划设计，而不是给每个字段都加索引。

### 52. 什么是联合索引最左匹配？

对于 `(player_id, created_at)` 联合索引，查询以 player_id 作为前缀时通常可以高效使用；只查询 created_at 通常不能完整利用这个索引。聊天历史、邮件分页和玩家流水需要根据实际查询顺序设计索引。

### 53. 什么是隔离级别？

隔离级别控制事务之间互相可见的程度，常见有 Read Uncommitted、Read Committed、Repeatable Read 和 Serializable。隔离级别越高通常并发成本越大。领奖和资产更新不仅要选择合适隔离级别，还要配合行锁、唯一约束和幂等流水。

### 54. 什么是死锁，数据库死锁如何处理？

两个事务互相持有对方需要的锁就会死锁。数据库通常会回滚其中一个事务，应用要捕获错误并有限重试。业务上还应固定更新顺序、缩短事务、为查询加正确索引，避免批量任务长时间占锁。

### 55. 什么是慢 SQL？

执行时间过长、扫描行过多、排序或临时表代价高的 SQL 都可能是慢 SQL。应使用 EXPLAIN、慢查询日志、索引分析和线上耗时指标定位，不能只凭数据库 CPU 高就直接加索引。

### 56. Redis 常见数据结构怎么用？

String 适合 Token、计数和简单值；Hash 适合对象字段；Set 适合黑名单和去重；Sorted Set 适合排行榜和按时间排序；List/Stream 可用于队列或消息流。项目中的 Session、未读数、在线状态和聊天缓存需要根据过期和一致性语义选择结构。

### 57. Redis 分布式锁有什么风险？

锁必须有唯一值、过期时间和安全释放逻辑，不能删除其他请求持有的锁；网络延迟、锁过期和进程暂停可能导致两个持有者同时执行。对于发奖等高价值操作，Redis 锁不能替代数据库事务和唯一幂等约束。

### 58. 什么是 CAP？

在网络分区发生时，分布式系统通常无法同时保证强一致性和完全可用性，只能在一致性与可用性之间取舍。游戏后端中玩家资产倾向于优先一致性，在线状态和聊天在线人数可以接受短暂最终一致。

### 59. 什么是最终一致性？

不同副本暂时不一致，但经过重试、消息补偿或缓存刷新后最终趋于一致。比如 MySQL 保存聊天事实，Redis 保存最近消息缓存，缓存短暂旧并不改变数据库事实，但必须有失效和重建策略。

### 60. 什么是消息队列？

消息队列把生产者和消费者解耦，可削峰、异步化和重试。当前 Worker 主要基于任务表轮询，未来可以把批量邮件和发奖任务迁移到队列，但仍需要消息确认、幂等、死信和重试上限。

### 61. 什么是熔断、降级和限流？

限流限制请求速率，防止系统被打满；熔断在依赖持续失败时暂时停止调用，避免故障扩散；降级返回缓存、默认结果或关闭非核心功能。登录限流、聊天频率限制和可选 LiveKit 服务都可以使用这些思想。

### 62. 如何测试一个后端接口？

至少覆盖成功、缺字段、类型错误、未登录、无权限、资源不存在、重复请求、并发请求、数据库异常、缓存异常和超时。接口测试要检查状态码、业务错误码、数据变化、幂等结果和审计日志，不能只测试 HTTP 200。

### 63. 什么是单元测试、集成测试和冒烟测试？

单元测试测试独立函数或 Service，Repository 可以使用内存实现；集成测试连接真实 MySQL/Redis，验证 SQL、事务和序列化；冒烟测试确认服务启动后健康检查、登录、玩家资料和关键链路可用。项目的 `smoke-http.ps1` 属于最小冒烟验证。

### 64. 如何做后端压测？

先确定场景、并发数、请求比例、数据规模和成功标准，再逐步增加负载，观察 RPS、P95/P99、错误率、CPU、内存、连接池、MySQL 和 Redis。压测数据必须隔离测试账号和数据库，避免把重复领奖、真实邮件或真实玩家数据混在一起。

### 65. 如何定位线上崩溃或异常？

先保留时间、Trace ID、服务实例、请求路径、错误码和最近部署版本，再查看结构化日志、core dump、调用栈和依赖状态。修复后增加回归测试和监控指标，避免只修改一行代码后认为问题永久解决。
